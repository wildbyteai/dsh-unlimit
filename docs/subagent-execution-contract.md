# 子代理限额的隔离执行合同

目标为 macOS arm64 的 DSH `0.2.1-rc.2`。本合同补充 `CORE-SUBAGENTS` 的执行证据，不改变 [117 项验收基线](parity.md)。测试加载完整官方 standard 预设、真实 Loader/Registry、SubagentRuntime、进程内 spawn 与 AgentLoop；只在模型传输处提供原创合成响应。

## 两类限额

运行控制中的 `maxSubagents` 对同一连续驻留父子链形成的活动代理树共享计数，孙代理也占用该池；两个独立根会话有各自的池。这里不推断冷恢复、跨进程或断开的父子链如何计数。插件默认值 16、官方默认值 8 与演练本地执行槽默认值 3 是不同配置。

`Flow` 执行槽按演练项目管理，只由经过工作流的分派领取。直接调用官方子代理接口不会自动领取本地槽。调整本地槽数不改变官方子代理限额，调整官方限额也不改变本地槽数。

深度 0 禁止创建第一层子代理，1 允许一层，2 允许孙代理。本次调用方每次先调用官方 `resolveMaxDepth()`，再把结果传入 `startActivation` 的 `maxDepth`，与本项目工作流调用方式一致。没有验证模型的 `subagent` 工具分派，也没有证明任意直接 API 调用都不能覆盖深度参数。

## 已执行场景

`tests/subagent-limits-host.test.mjs` 的四个场景和父测试共 5 项：

- 数量 1 → 2 → 1：下一次创建读取新值，降低上限保留已运行代理；满额真实拒绝，释放后可用同一先前被拒绝的 ID 再次创建。
- 深度 0 → 1 → 2 → 1：实际创建子、孙代理；超深请求由官方错误拒绝，降低限额不会主动停止已有孙代理。
- 两个根的池相互独立，同一驻留树的子、孙代理共享池；本地 Flow 槽满与官方池满分别验证。
- 撤销恢复原冻结配置引用及官方深度 1、数量 8；实际接纳 8 个子代理、拒绝第 9 个，释放后再接纳。

共创建 18 个真实子／孙代理，12 次请求被原生拒绝。拒绝时核对无代理注册、无生命周期启动、无模型请求、无会话或 JSONL，父事件不变。18 次执行经官方 JSONL 读回，所有执行者与 5 个根均完成处置；网络守卫无触发，临时根清理完成。[结构化证据](evidence/subagent-limits-acceptance.json) 绑定实际加载文件和项目源码摘要。

这里的“真实”仅指官方模块实际执行，模型传输仍为合成数据。没有安装到桌面、执行模型工具、连接真实模型或读取真实 profile。该边界只描述测试 fixture；开发操作异常另见 [验证记录](verification.md#子代理限额与首轮角色正文2026-10-21)。
