# dsh-unlimit 用户指南

适用目标为 **DeepSeek Harness 桌面端 0.2.1-rc.2、macOS arm64**。本版本为 0.1.0；源码实现、合成测试、官方模块隔离执行与真实桌面验收分别记录。目前尚未安装到真实 DSH 做验收，不能视为全部桌面能力已通过。

## 开始使用

通过官方插件管理器加载后，从 **U · 工作台** 进入。普通设置用于配置自写正文、规则和运行控制；演练区用于管理项目、资产、证据和任务。保存设置后检查诊断，再主动应用；默认安装状态不启用运行控制。

![桌面工作台，图中为合成数据](ui-preview.jpg)

规则的“适用模型”按模型 ID 完全匹配，留空表示全局规则。同一模型有多套规则时，明确激活的那一套优先；未激活该模型的某一套时，沿用列表中第一条匹配规则。模型专用规则优先于已激活的全局规则，但不会应用到其他模型。清除激活只清除手动选择，模型匹配仍有效；需要停止全部规则注入时使用“还原运行控制”。

还原时仍在等待组装的提示词会沿用宿主原文；马上重新启用也不会让旧任务继续注入。已经发送的请求和既有对话记录不会被撤回。

同一轮执行工具后修改正文，以及失败重试时，下一次请求使用当前整段正文，不叠加旧版本。对本次启用已接管且仍驻留的会话，撤销后下一次正常发送前恢复宿主正文；此前取消或被策略拒绝不会丢失恢复机会。撤销本身不发送消息。尚未接管的分支、已卸载会话和跨重启恢复仍未覆盖，详见[提示词与还原范围](https://github.com/wildbyteai/dsh-unlimit/blob/main/docs/prompt-sections-contract.md)。

在“系统提示词”中打开“预览已保存正文”，填写模型 ID，即可查看将采用的规则或保存正文；模型留空时只考虑全局活动规则。选定的工作区文件需要参与正文时，再填写该工作区的绝对目录。预览显示来源、配置版本和完整候选正文，采用与运行时相同的选择逻辑；未保存的编辑不会计入，也不会因此启用控制或发送模型请求。宿主工具说明和会话角色段不在此预览内。

## 功能与限制

- 替换或追加系统正文，保留模式、PTC SDK、MCP 等功能说明；保存多套规则、按模型选择规则、选择本地工作区规则，每轮与重试读取当前正文。
- 通过已核验的原生接口，按 strict / fallback / always 处理工作区基线及刷新消息；历史保留原日志，切回保留或还原时恢复仍由本插件持有的节点。原生入口摘要不符时明确不支持，当前只完成官方隔离验收。
- 从宿主目录选择未来新会话的默认权限预设，配置未明确选定策略时的审批和访问行为、子代理数量与深度。已有会话和显式选择保持有效；撤销恢复未来默认，不回滚已创建会话。
- 子代理并发上限由同一连续驻留代理树共享，包含孙代理；独立根会话分别计数，演练执行槽另行配置。深度 0 禁止新建子代理，1 允许一层；降低限额不主动停止已经运行的代理。
- 子代理按创建时的父会话权限运行；父会话随后切回受限不会自动撤回已有子代理的权限。显式限制继续优先于插件的完整访问设置，委派审批沿用宿主规则。
- 读取预算只调整官方 read 的正文窗口，已有工具消息保持宿主原有历史与压缩语义。应用时覆盖当前启用 read 的全局与预设条目，分别保留原配置；原本关闭的 read 不启用。页面显示覆盖数量，新加载的预设需重新应用。发行摘要不符或配置被外部更改时显示诊断，不覆盖外部修改。
- 按需关闭官方重复调用建议提醒，恢复时沿用原配置。工具拒绝与取消仍有效；配置不写入宿主 profile，外部修改发生冲突时保留。
- 按需接管模型请求的重试次数（0–20），沿用官方退避、Retry-After、取消和日志；默认沿用提供方策略。
- 对根会话明确的输出长度截断手动继续，或启用有次数上限的自动继续。启用控制后创建的受管本地子代理也可在当前任务内自动续轮；工作流保留名额，等整个任务结束才释放并启动后继任务。保留插件消息来源，用户停止、传输错误和限流不会触发新轮次；自动继续默认关闭，手动继续不重置自动次数。
- 已结束的本地子会话可在“会话管理 → 继续状态”查看是否允许手动继续。只恢复最新自有输出明确因长度上限截断的官方本地持续子会话；运行中、父会话未驻留、父子已归档或已有后续输入时拒绝。确认将采用当前保存的继续用语、提示词和角色创建新执行，可能产生模型调用费用，并按宿主行为通知父会话。详情显示新执行状态、运行标识与名额；原工作流收据和已完成依赖图保持不变，演练子任务需重新取得名额并持有到原生执行结束。
- “停止本插件续跑”撤回待接纳请求、移除本插件所属输入，并在确认运行归本插件独占时停止它。其他来源的输入保留；普通停止遇到它们会等待原生执行结束后释放名额。撤销插件控制时可能显示“控制权已释放”，只表示插件放弃控制及名额，宿主任务可能继续。此手动恢复已有五项官方模块隔离场景通过，真实桌面嵌入尚未验收。
- 创建、编辑、导入、覆盖、删除技能，通过宿主技能目录发现它们。支持 ZIP、SKILL.md 和文件夹，单次新导入最多200个普通文件；覆盖与删除保留本地备份。
- 按会话读取宿主技能、工具和本项目技能的来源与正文，预检明确声明的工具、目录、变量、主机登记和私钥元信息；未声明或来源不可用时显示未知。
- 用新界面管理演练项目、资产与服务、发现、证据、关系图、阶段评分、共享知识、原创角色稿和 Markdown 报告。
- 在 WebShell/隧道台账中预览并确认一次连接检查：HTTP HEAD 或明确监听端的 TCP 连接，分别保存实际结果、时间和延迟，支持取消与过期标记。按精确主机、已刷新的派生 IP 或本地国家数据选择允许地址；[连接检查合同](https://github.com/wildbyteai/dsh-unlimit/blob/main/docs/connection-checks-contract.md) 说明边界。
- 手动导入本地国家 CSV/gzip，查看数据月份、摘要与归属；明确确认后刷新已登记域名的解析快照。无例外的 CN/HK/MO、未知及特殊地址不连接，别名和子域不继承例外。数据库不内置、不自动下载，见 [范围合同](https://github.com/wildbyteai/dsh-unlimit/blob/main/docs/network-scope-contract.md)。
- 应用运行控制后，对主／子代理的现有 `web_fetch` 本地 HTTP 路径执行同一范围判定，每跳核对身份、范围版本并固定允许地址。HTTP 与本地连接检查按当次 DNS64 发现判定 IPv6／译址 IPv4 的地区；发现不明且无例外的 IPv6 拒绝。保留官方工具权限和 public-only 拒绝；代理、远端 Fetch 明确未支持。MCP、终端、搜索和浏览器出口仍未覆盖，见 [HTTP 合同](https://github.com/wildbyteai/dsh-unlimit/blob/main/docs/web-scope-contract.md) 与 [IPv6 合同](https://github.com/wildbyteai/dsh-unlimit/blob/main/docs/nat64-contract.md)。
- 凭据登记可关联资产与服务、记录角色和来源；API 与模型只读回元数据和保存状态。编辑时留空保留秘密，填新值替换，明确勾选才清空；密码不进入页面草稿。
- 保存工作区文本、文件和图片证据，核对摘要、预览图片；覆盖或删除保留可恢复备份。按已登记的资产关系查询最短路径。
- 将会话明确绑定到项目；模型工具与页面使用同一数据服务，子会话继承项目绑定。
- 模型写入后，切页或点击右上角“刷新数据”读取最新内容；左侧“有更新”与证据分类圆点按项目独立保留。初次打开建立基线，提醒不是新增条数；不会后台自动刷新，读取失败会保留提醒。面板内刷新保留草稿，浏览器重载会丢失内存草稿和已读状态。
- 从已绑定的父会话分派明确任务，先领取本地槽位再创建官方执行者；查看收据、停止并确认释放。可注册和撤销本项目的原创运行时预设。
- 角色正文按明确的工作区与角色分配注入；需要已应用运行控制且总开关启用。释放并发槽不撤销角色分配，撤销角色需明确清除分配。
- 提交带明确依赖的多任务计划，按槽位排队，把前序原始结果传给直接依赖任务；缺依赖、失败或清理未确认均可读回。计划只保留于本次运行，不内置自动任务拆解。
- 演练入口有当前安装的阅读、倒计时与逐项确认，支持撤销并重试清理所属执行者；该确认不授予任何目标访问权限，普通设置独立可用。
- 管理本地普通/秘密变量、连接主机和私钥路径元信息；秘密不读回正文，不进入页面草稿。配置使用文件权限保护，未加密，也不自动注入进程或提示词。
- 管理本插件启动的本地工具任务：先配置可执行文件路径，在绑定项目的会话中通过 `unlimit_process` 的 `start` 提供工具标识和参数；在“工具与环境”页手动刷新列表、查看输出或停止任务。启动沿用宿主会话权限与审批，保存路径不会启动任务。输出最多保留每路 64 KiB，截断和未确认清理会明确显示；重载后不保留历史输出。
- 通过官方会话接口准备回退、创建分支并归档旧会话；文字、图片与文件草稿分别报告恢复状态，文件通过官方上传生成新收据。子代理默认按创建来源定位，也可选择“最近接纳输入”；后者需要启用运行控制期间记录的标准 send_message 关联，旧日志缺记录时拒绝。
- 回退后的待办以保留步骤的列表为准。仅将在该列表中进行中、并在被切除的同一轮内连续保留且最终完成的同名任务恢复为待开始；较早已完成任务保留，后续新增任务不带回，跨轮、重命名或删除重建不作关联。更新只写入新分支并沿用官方工具策略和审批；原会话的任务不变。结果显示已确认的恢复数量或“待办恢复未确认”。下一轮仍按宿主行为清空待办，不自动重新应用。
- 若当前 PTC 等模式限制待办工具调用，回退可能停在已创建新分支、尚未归档原会话的阶段；等待时新分支接纳其他输入或插件关闭也会取消恢复。工具执行后被策略拒绝时，可能已有待办写入；即使显示待办已恢复，整体仍会标明回退未完成，请按新会话编号检查。此能力范围见[会话附件与任务合同](https://github.com/wildbyteai/dsh-unlimit/blob/main/docs/session-attachments-contract.md)，完整 SESSION-VIEW、附件和子代理映射的真实桌面操作及外部任务恢复仍未验收。
- 配置逐工具路径、工具根、额外目录和模板目录，运行固定版本/帮助检查，区分两个同名的 `httpx` 产品。登记资产、凭据或会话不会执行远程操作。
- 按路径或正文检索本地模板、读取全文与摘要，再整理为带来源的未验证知识条目。页面未保存编辑按对象保留在内存中，刷新前会提示。

没有自动更新、激活服务、分析埋点或其他插件作者的服务依赖。模型请求仍通过使用者配置的宿主模型服务发送；“本地维护”不表示在线模型变成离线模型。

## 安装、还原与资料保留

先关闭其他执行同类运行时修改的插件，备份桌面 profile。若应用本体已有其他工具的修改，先按其恢复流程恢复；本项目不负责覆盖其他工具的修改。

0.2.1-rc.2 的官方插件管理器支持绝对本地目录和 tarball 路径。将构建后的 `.tgz` **绝对路径**作为安装来源，核对名称 `dsh-unlimit` 后使用官方安装流程。此仓库未在真实用户 profile 上执行该流程；若你的桌面界面没有本地来源入口，应先核对宿主能力，不手工改写应用文件。

加载后通过 **U · 工作台** 打开页面。先填写自写正文、检查诊断状态，再主动点击应用。聊天入口为 `/unlimit status`、`/unlimit apply`、`/unlimit revert`。默认安装状态不启用运行控制。演练区需完成本安装的入口确认；工具与环境可明确选择暂不配置，均不修改宿主的普通聊天权限。

还原只撤销本插件的运行时修改，保留规则、技能及台账。诊断页的“卸载本插件（保留资料）”在确认后先持久禁用、撤销演练确认、停止所属任务并恢复运行控制，再调用官方插件管理器并读回结果。清理失败不移除，未知结果不自动重试，不自动重启；仅匹配当前实例的profile安装包才开放入口。直接从官方插件管理器卸载不经过这条准备链，入场确认清理尚未覆盖；真实桌面卸载也尚未验收，见 [卸载合同](https://github.com/wildbyteai/dsh-unlimit/blob/main/docs/maintenance-contract.md)。持久数据位于当前桌面 profile 的 `data/dsh-unlimit/`；备份时应退出插件后复制该目录。不要直接删除其中的数据库或技能备份。

## 诊断与适配

从源码目录运行 `npm run doctor -- --app "/Applications/DeepSeek Harness.app"` 可只读检查版本和必要模块；从已解压安装包运行 `node src/cli.js doctor --app "/Applications/DeepSeek Harness.app"` 使用同一入口。此命令不安装插件、不改配置，也不等于实际会话功能验收。

当前版本只对上述宿主版本开放适配检查。入口摘要不符或官方接口缺失时，诊断显示不支持；不能靠改版本号跳过。对正在使用的安装应先查明原有修改的来源，本插件不会覆盖应用文件。

已验证范围与未完成项见仓库的[验证记录](https://github.com/wildbyteai/dsh-unlimit/blob/main/docs/verification.md)和[功能验收清单](https://github.com/wildbyteai/dsh-unlimit/blob/main/docs/parity.md)。其中真实桌面加载、完整模式执行、部分 Hook/记忆策略及未覆盖的网络出口仍有缺口。后续版本适配按[维护流程](https://github.com/wildbyteai/dsh-unlimit/blob/main/docs/maintenance.md)执行。
