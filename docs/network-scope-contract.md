# 本地范围判定

对应 SCOPE-EXACT、SCOPE-REGION 的独立实现，当前执行入口为本插件 WebShell / TCP 连接检查。SCOPE-ENFORCE 的主会话、子代理、其他工具和全部网络出口仍未完成。登记、入场确认或国家分类不构成目标所有权证明；每次检查仍需明确确认。

## 地区数据

数据库由使用者在控制页选择本地 CSV / CSV.gz 导入，不内置、不自动下载，不向外部地理定位服务查询地址。解析器按 [DB-IP Lite 的 CSV 格式](https://db-ip.com/db/format/ip-to-country-lite/csv.html)独立编写：UTF-8、RFC 4180、三个字段 `ip_start,ip_end,country`，支持引号、CRLF 与可选同名表头。只接收 IPv4 在前、IPv6 在后、范围起点递增且不重叠的记录。跨族、倒置、重复、非法 IP 或国家代号拒绝；空值、XX、ZZ 表示未知，不能当作其他国家允许。

CSV 最大 48 MiB；gzip 最大 16 MiB，展开最大 64 MiB；最多 150 万行。文件名只标识格式，不解析成本地路径。解压后原 CSV 字节的 SHA-256 可读回；`release` 是导入者填写的 YYYY-MM，**不表示供应商真实性验证**。`source: db-ip-lite` 标识所采用的格式，合成测试数据不来自该供应方。数据保存到插件自身目录的 `region.sqlite`，查询通过 SQLite 主键索引按范围查找，不逐行扫描。

导入必须提交当前数据库 revision；版本为 `SHA256(JSON.stringify([sha256,release]))`。修改月份也改变 revision。新库完整验证后原子替换，非法输入、冲突或替换失败保留旧库。关闭后不接受操作；路径、符号链接、异常数据库拒绝时不回显原始内容或本地路径。

[DB-IP Lite 下载说明](https://db-ip.com/db/download/ip-to-country-lite)列出其数据的 CC BY 4.0 归属要求；页面保留 [DB-IP](https://db-ip.com) 与 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 链接及归属元数据。本项目包不包含该数据库，也没有接受其下载页面上的协议或验证其实际月度数据。国家数据可能不完整或不准确，用户提供的月份和摘要不能替代来源核验。

## 登记与解析快照

已有 `ownServers` 输入规则保持：IP、完整主机名或 user@host；不接受凭据、URL、网段、端口及通配符。用户名不参与匹配、DNS 或连接。IP 和 IDNA 主机标准化，IPv4-mapped IPv6 采用相应 IPv4 语义。

保存清单、打开页面、状态读取、导入数据、预览检查均不查 DNS。用户在控制页明确确认后，才对选中的 1–32 个已保存域名调用系统解析器；每个域名最多 6 秒。一批中成功的结果在末尾保存，失败项保留原快照并返回本次失败。停止、入场撤销或范围变化使本批新结果失效，不覆盖旧结果。快照有地址列表和解析时间，不设隐含自动刷新或 TTL。

派生例外只允许直接使用该快照中的字面 IP；另一个域名或子域即使共享该 IP，也不继承例外。刷新成功替换原地址集合。修改保存的服务器清单清空所有派生快照；移除再添加不能恢复旧例外。精确登记的主机本身可在实际检查时使用其当次解析出的地址，无需预先保存快照。

解析失败保留旧快照意味着其仍然可用；页面明确区分最后保存的快照和本次失败。需要撤销旧例外时修改清单。无效存储返回 `NETWORK_SCOPE_PARTIAL` 和实际已观察但未保存的结果，不声称例外已经建立。

## 逐地址决定

| 情况                                                 | 当前决定                           |
| ---------------------------------------------------- | ---------------------------------- |
| 精确登记主机 / IP                                    | 例外允许；不依赖地区库、不查询国家 |
| 字面 IP 命中已登记域名的保存快照                     | 派生例外允许                       |
| 无例外，国家为 CN、HK、MO                            | 拒绝                               |
| 无例外，明确归入其他有效国家代号                     | 允许本次已确认的检查               |
| 无例外，特殊地址 / 私网 / 回环 / 转换地址 / 文档地址 | 拒绝，即使 CSV 为其填写国家        |
| 无例外，数据缺失 / 未覆盖 / 未知国家 / 无效地址      | 拒绝，不猜测归属                   |

特殊地址判定先于 CSV 查询；IPv6 非当前全球单播范围及已识别的特殊段不被当作外国公网。这里的规则是本项目明确选择的行为，不能宣称已经复现旧项目未公开的数据源、缓存寿命或所有特殊地址处理。

未登记域名在地区库可用时预览为 `ready / region-pending`；表示确认后可开始解析和判定，**不是已允许连接**。确认后取得 A/AAAA，逐项判定并只选第一个允许地址，混合受限/允许答案不一概放行或整域拒绝。无允许项时目标连接数为零。只连接选定的 IP；HTTP Host / TLS 主机校验保持原域名，不再次解析、不跟随跳转、不重试其他候选。现有 HEAD/TCP 语义见 [连接检查合同](connection-checks-contract.md)。

确认摘要绑定台账、入场版本及范围 revision；范围 revision 包含保存主机、DNS 快照和数据库 revision。DNS 后、保存回执前再次核对；变化则取消或披露实际观察结果但不写为当前有效结果。历史回执的记录或范围版本变化会标记过期。

## 本地 API 与生命周期

以下动作仅在宿主认证后的本机同源 UI 开放，不加入模型工具白名单：

| 动作                   | 输入与结果                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------- |
| `networkScope.status`  | 无输入，返回 `revision,active,database,hosts`；只读                                       |
| `networkScope.import`  | `filename,release,contentBase64,revision`，revision 为当前数据库版本；返回新状态          |
| `networkScope.resolve` | `hosts,revision,confirmed:true`，revision 为当前范围版本；要求入场，返回 `{items,status}` |
| `networkScope.stop`    | 等待本插件解析任务结束，返回 `{stopped:true}`                                             |

`hosts` 每项有 `hostname,type,snapshot`；snapshot 包含 `addresses,resolvedAt`。解析回执包含 `hostname,state,reason,persisted` 及实际观察到的地址和时间。检查回执另有 `scope:{allowed,reason,country,address,matchedHost?,databaseRevision?}`；精确例外的 `country:null` 表示未查询，不冒充地区定位。

撤销入场、清单变化、卸载准备和 dispose 均取消解析。数据库/快照改变时取消在途连接检查并使旧确认失效。卸载先取消自有任务再等待已接纳动作；数据库最后关闭，资料不删除。

## 已验与未验

合成 CSV、假 DNS、临时 SQLite 和官方挂载入口有自动测试；浏览器实际操作覆盖本地文件选择与导入、取消确认、解析停止、混合地址选择、别名拒绝、保存与刷新读回，见 [验收证据](evidence/network-scope-acceptance.json)。预览所有目标 DNS 和传输均为合成回调，只有页面服务监听回环。它不证明真实国家数据准确、外部目标可达或桌面嵌入已通过。

官方 0.2.1-rc.2 边界调查确认 `web_fetch → HttpFetchProvider` 有每跳解析接口，但其代理分支会绕过该接口；原生 public-only、IPv6 NAT64 检查、远端 Fetch、MCP、shell 和 Chromium 各有不同执行路径。本轮没有接管它们，也没有用工具名称或命令关键词冒充逐请求出口控制。
