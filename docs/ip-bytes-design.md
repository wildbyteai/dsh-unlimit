外部实际阅读的资料（2026-10-21）：

- [RFC 4291 §2.2](https://www.rfc-editor.org/rfc/rfc4291.html#section-2.2)：八个 16 位十六进制组、一次 `::` 零组压缩和末尾四个十进制字节的表示规则。测试数据自行构造，没有复制该节示例。
- [Node 官方 `net.isIP`](https://nodejs.org/api/net.html#netisipinput)：读取到的网页标示 v26.12.0，API 说明包含严格点分十进制、无前导零及映射地址返回 IPv6。尝试访问 `latest-v24.x` 文档时浏览工具未能读取；实际执行验证固定使用宿主附带 Node v24.21.0。未读取 Node 的实现源码。

没有复制网络实现、转换示例或其他插件代码；标准 API 调用、网络字节序与协议文本结构本身并非本项目独有。

## 合同与实现

`parseIpBytes(input)` 不执行 I/O、DNS 或网络访问，也不引入第三方依赖。非字符串、超过 45 字符及允许字符集之外的输入先返回 `null`；因此空白、scope、CIDR、方括号等不能进入语法判定。`node:net` 的 `isIP` 判定剩余输入是否为完整地址，不对用户对象做字符串转换。

有效 IPv4 的四个十进制段逐个写为字节。有效 IPv6 的十六进制组逐个写为高位字节、低位字节，嵌入的 IPv4 尾部直接贡献四个字节。`::` 左侧字节靠左，右侧字节靠右，中间由新建的零填充 Buffer 补足。没有 `::` 时，完整字段占满 16 字节。语法已由 `isIP` 验证，转换过程不再维护第二套语法校验器。

返回值为 `{ family: 4 | 6, bytes: Buffer }`。每次调用新建 4 或 16 字节的可写 Buffer；IPv4-mapped IPv6 保留 `family: 6` 及完整 16 字节，折叠策略属于调用方。

## 验证设计

测试以原创固定向量检查字节顺序、大小写、前导十六进制零、IPv4 尾部及映射地址。两组确定性用例先规定原始 octet，再构造文本表示；期望值不调用被测解析器，也不从解析后的组数推导。纯 IPv6 覆盖全部 36 个连续零组区间；带 IPv4 尾部覆盖前六组内全部 21 个区间。256 个 IPv4 输入让每个字节位置遍历 0–255。无效值覆盖类型、长字符串、各类包裹/扩展语法、字段数与数字边界；另外验证调用之间 Buffer 的独立可写性。
