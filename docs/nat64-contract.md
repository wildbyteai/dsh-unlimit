# IPv6 译址与地区判定

覆盖当前桌面 HTTP 适配及本插件明确确认后的连接检查。地址国家取自使用者导入的本地数据库；DNS64 发现只用于识别应查询哪个地址，不提供国家数据，也不证明目标授权。

## 发现与解码

独立实现依据 [RFC 6052 §2.2–2.3](https://datatracker.ietf.org/doc/html/rfc6052#section-2.2) 的六种布局（/32、/40、/48、/56、/64、/96）及 [RFC 7050 §3](https://www.rfc-editor.org/rfc/rfc7050.html#section-3) 的 `ipv4only.arpa` 发现规则；该域名的特殊用途见 [RFC 8880](https://datatracker.ietf.org/doc/html/rfc8880)。`src/core/nat64.js` 只解释调用者提供的 DNS 快照，没有网络、缓存或外部依赖。

- 有效 A 答案仅含 `192.0.0.170 / 192.0.0.171` 且没有 AAAA，视为此次未发现 DNS64 前缀。
- AAAA 必须能按标准布局解释为上述发现地址。地址出现位置不唯一时，用另一发现地址的无歧义证据消歧；仍不能确定、格式非法、记录超过 256 条、空答案或部分 AAAA 无法解释时，整个发现结果为未知。
- 目标匹配已发现前缀时，取其中编码的 IPv4 作为地区查询地址。保留并固定原 IPv6 作为连接地址，不把 IPv4 直接交给传输。
- `u` 字节必须为零，包括 /96。非零 suffix 按标准忽略；匹配多个前缀但译址结果不同则拒绝判明。没有匹配前缀且发现有效时，按原生 IPv6 查询地区。
- IPv4-mapped IPv6 的 IPv4 语义固定，沿用现有 IPv4 归一化和特殊地址检查，不依赖发现成功。

未知发现的无例外 IPv6 不连接；可以选择同一答案集里已经允许的 IPv4。HTTP 仍先执行原生完整答案集检查，所以原生 DNS 或 public-only 拒绝不会为了备选地址而被忽略。

这是系统 DNS 答案驱动的发现启发式。它不能发现所有自定义翻译机制，也不能抵御恶意 DNS 或证明网络实际采用某个前缀；没有将普通 DNS 结果包装成加密证明或系统出口防火墙。

## 两个执行入口

### 官方 HTTP 工具

仅对摘要、默认 resolver 身份和运行时接口已通过版本门的 **0.2.1-rc.2** 生效。该版本原生 `resolveAddresses` 的第三个 lookup 参数原本用于定向测试；本适配向它提供透明观察函数，仍调用系统 `node:dns/promises.lookup` 并原样返回答案。只复制原生本次已经取得的 `ipv4only.arpa` 地址元数据，**不增加第二次发现查询**、不替换共享 resolver、不改变原生完整答案集验证。

这个参数不是跨版本稳定承诺，升级必须重新核验。每次调用、每跳同源跳转各持有自己的快照；不在主／子代理、并发调用或跳转之间缓存。未见一次明确发现不能当作无 DNS64。解析后仍复查身份、范围 revision、代理和接口所有权。

原生限制先于国家例外：即使精确登记，原生私网、混合私网答案及译址私网拒绝仍有效。其他 HTTP 语义见 [HTTP 合同](web-scope-contract.md)。

### 本地 WebShell / TCP 检查

读取、保存、预览不发现。确认执行后，仅有无原目标例外的 IPv6 候选时，经现有系统解析边界发现一次，使用与目标解析、连接相同的每项总时限。精确主机／派生字面 IP 例外沿用原有路径，不新增发现请求。

发现失败使相应 IPv6 候选不明；已有允许 IPv4 仍可使用。取消、预算耗尽或范围／入场／记录变化则不连接。没有跨检查缓存，发现域名只用于 DNS，绝不作为 HTTP/TCP 检查目标。确认说明在页面显示新增 DNS 行为。

## 决定与回执

对无例外 IPv6 字面地址，执行入口在地区库可用时延后表面地区预判，直到当次发现完成。数据库缺失仍拒绝。译址目标 CN/HK/MO、未知或特殊地址按共享规则拒绝，即使原 IPv6 表面地区允许；反之允许的 IPv4 不因 IPv6 表面国家被误拒绝。

精确和派生例外始终匹配原目标。把译址后的 IPv4 登记为例外，不会自动放行一个不同的 IPv6 目标或域名。内部 `decide(target,address,{ipv4Destination})` 保持字面目标与连接地址一致，第三参数不向模型或 UI API 开放。

连接检查回执的 `scope.address` 保留候选连接地址，译址时另有 `scope.countryAddress` 作为国家判定依据。页面区分“连接候选”和“译址目标”；只有实际传输结果才有 `transport`。不明原因是 `ipv6-unverified`，HTTP 对应 `WEB_SCOPE_IPV6_UNVERIFIED`，不伪装为离线。

范围 revision 加入 `dns64-v1` 判定版本。升级前的检查回执仍保留，但标记过期，不能把旧的 IPv6 表面地区结论当作已通过新规则；无需删除历史资料或修改原服务器解析快照。

## 验证边界

使用原创合成地址、临时国家数据库和假 DNS。官方工具测试执行真实 ToolRuntime / web_fetch / HttpFetchProvider，HTTP 响应由 MockAgent 提供；固定 lookup 验证在真实连接器进入 `tls.connect` 时记录地址并立即终止，未创建真实 socket。页面验证使用任务所属回环预览。未安装插件、未修改真实 profile，未验证真实 DNS64 网络、真实国家数据准确性或桌面嵌入。
