# 现有 HTTP 工具的范围执行

适配 **DSH desktop 0.2.1-rc.2** 的 `ToolRuntime → web_fetch → WebRuntime → HttpFetchProvider`。复用[本地范围判定](network-scope-contract.md)，不注册替代抓取工具，不分发宿主实现。范围决定是额外约束，不是目标所有权或任务授权。原有工具 pre-policy、guard、审批、取消和输出策略仍由官方调度器执行。

## 启用与归属

使用已有的“应用运行控制／还原运行控制”。`webScope` 能力显示 `available / active / unsupported` 和具体边界；只有适配仍持有所需接口且运行控制开启时才执行限制。缺少 HTTP 插件、未知版本或不匹配的入口显示未支持，不把其他控制的成功当作网络范围已经生效。

应用前核对桌面版本、相关官方入口的发行库存 SHA-256、唯一活动 HTTP 插件条目、模块回调、实际 Web/Tool/Agent 类、provider 实例、默认解析器及活动 limits。Cordis 服务先消除 trace proxy 再比较身份。应用不修改宿主配置、provider 注册表或磁盘代码。

`tools/execute` 只携带明确的调用归属。实际抓取处要求：调用尚未结束、`exec.agent` 未变、注册表中的活动 Agent 和 `currentInitiator()` 都是同一对象。主／子代理用各自的真实身份，并发调用不共享解析器。无归属、身份不一致或调用结束后的异步遗留工作拒绝。普通会话不额外要求演练入场或工作区绑定；这些条件不被当作网络操作授权。独立的本地连接检查仍沿用其人工确认合同。

## 每次抓取与每跳连接

1. 按官方配置的选择语义检查当前 provider。只接受已核实的 `http` 实例；缺失、不可用或歧义保留相应的 `WEB_PROVIDER_*` 错误。远端 Fetch 返回 `WEB_SCOPE_PROVIDER_UNSUPPORTED`，不调用其抓取方法。
2. 每个调用建立独立的官方 HTTP provider，保留活动 limits，包括 GET、正文限制、超时、同源重定向及关闭逻辑；仅组合其默认解析器和逐跳检查。不会在并发调用间替换共享 resolver。
3. 官方 URL 校验先执行。每跳检查代理路由；代理无法提供已核实的目标地址，返回 `WEB_SCOPE_PROXY_UNSUPPORTED`，不静默改为直连。范围预览已拒绝的目标不再发起目标 DNS。
4. 使用原生解析器验证完整答案集。私网／回环／不合规答案、凭据 URL、跨源跳转等原生拒绝不被精确例外覆盖。原生 IPv6 解析还可能查询 `ipv4only.arpa`；这里不宣称“一次 DNS”或“所有字面 IP 零 DNS”。
5. 对通过原生检查的每个地址执行共享范围判定。只向官方固定 lookup 传入第一个可核实的允许地址，保留原 URL、Host 和 TLS 主机校验。混合国家答案不把被拒绝地址交给传输，不重试其他候选。每次同源重定向重新解析、重新判定。
6. DNS 完成、范围决定后和返回结果前复查调用归属、接口所有权、启用状态及范围 revision；解析后再次检查代理路由。变化时不使用旧决定开始连接或返回当前成功结果。取消信号贯穿官方请求和正文读取，收尾等待其原生关闭逻辑。

### IPv6 的当前边界

官方 resolver 验证 DNS64/NAT64 的 public-only 条件，但没有输出翻译前缀及最终 IPv4 目标。单凭本地库中的 IPv6 国家不能确认翻译目标的国家。因此无精确／派生 IP 例外的 IPv6 候选暂不采用；若没有合格 IPv4 备选，返回 `WEB_SCOPE_IPV6_UNVERIFIED`。精确例外可采用原生校验后的 IPv6，但这不是国家定位证明。这个限制保持为兼容缺口，不以测试中的假数据补成完整 IPv6 地区支持。

## 变化、撤销与错误

范围 revision 包含清单、保存的 DNS 快照和数据库版本。通过本插件更改这些内容会取消在途 HTTP 调用；即使变更动作部分失败，只要版本已变仍尝试取消。外部直接替换数据库在下次版本检查时被发现，没有后台轮询。已经发出的请求不能撤回；取消只阻止后续阶段并关闭本次资源。

还原、卸载准备和插件释放会先取消自己的在途调用。还原只恢复仍由本插件持有的属性；其他所有者的替换保留并报告冲突。应用失败会回滚已改动的接口，控制器不会将 `enabled` 保存为成功。

| 错误                             | 含义                                         |
| -------------------------------- | -------------------------------------------- |
| `WEB_SCOPE_CONTEXT`              | 工具和活动 Agent 归属不一致                  |
| `WEB_SCOPE_OWNERSHIP`            | 宿主服务、插件、provider 或适配方法发生替换  |
| `WEB_SCOPE_CHANGED`              | 控制已关闭，或范围版本已变化                 |
| `WEB_SCOPE_DENIED`               | 没有当前允许地址，或预览已拒绝               |
| `WEB_SCOPE_PROXY_UNSUPPORTED`    | 代理出口缺少可执行的目标地址合同             |
| `WEB_SCOPE_PROVIDER_UNSUPPORTED` | 选择的不是已核验的本地 HTTP provider         |
| `WEB_SCOPE_IPV6_UNVERIFIED`      | 无法核实 IPv6 翻译目标的地区，且没有允许备选 |

原生取消、URL、DNS、公有地址、重定向和正文错误仍沿用官方错误类型；范围错误通过官方 `WebError` 进入工具结果，不记录或回显 URL 查询中的秘密。

## 验证层级与剩余差距

[合成测试](../tests/scoped-http.test.mjs) 独立捕获传输输入；[官方接口测试](../tests/web-scope-host.test.mjs) 通过新建隔离 Context、合成 Agent 与假 DNS/HTTP 边界调用真实工具链。单独回环实验使用明确的测试 resolver，只证明官方传输的固定 lookup、原主机和收尾行为；生产适配门不接受这种 resolver。

这不是进程或系统防火墙。它不约束 Web 搜索、MCP 服务器及下游、Bash/Pwsh、外部进程、Electron/Chromium、其他插件保留的旧函数引用或自行建立的连接。已核验入口的摘要也不是整个依赖树或已安装应用的完整性证明。SCOPE-ENFORCE 保持部分完成，真实桌面安装与嵌入验收继续按用户决定暂停。
