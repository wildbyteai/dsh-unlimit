# 后续桌面版本维护

## 先确认正在适配什么

从新版官方安装只读获取 `desktop-runtime.json`、宿主版本和平台，运行 `npm run doctor -- --app <应用绝对路径>`。单独保留旧版安装或其可恢复备份；不要让旧插件的修改混入新版接口证据。

协议和官方模块检查会核对直接导入入口与安装清单的 SHA-256。不匹配时先查清该文件的来源，不关闭摘要断言、不将修改后的文件称为原始官方模块。当前检查不覆盖所有传递依赖。

`systemPrompt.project` 是当前版本的内部实例接口，升级时尤其需要复验。发生部分失败时不伪造完成，不直接编辑会话日志补救。

原生规则适配还依赖精确的事件来源和步骤时点。内存 Session 接纳成功不代表物理 JSONL 合法；升级必须运行 `native-instructions-host.test.mjs`，从落盘日志重建每次完整请求，并检验恢复、分支与取消。文件权限验收运行 `file-permissions-host.test.mjs`，不能以默认配置读回替代工具实际写入/拒绝。两项均需要显式官方运行时与可信公开归档目录；不执行摘要已变化的安装入口。

## 做最小可复验的改动

先在临时目录中运行失败场景，再修对应适配器。保持原生消息来源、工具说明、模型协议和用户明确权限选择；不能用“接口存在”代替实际请求验证。确认哪些旧补丁已经由新版原生行为满足，避免重新引入历史问题。

运行基础检查、官方服务检查和四协议请求检查；凡请求生成路径发生变化，检查首轮、第二轮改正文、子会话首轮和失败重试。会话变化另查分支内容、归档、停止与草稿恢复，不能只核对新会话 ID。继续、工作流、目录分别运行其 `*-host.test.mjs`，核对真实事件持久化、停止/清理及会话隔离；不能以模块可导入代替运行结果。

确认当前目标的测试通过后，更新 `SUPPORTED_HOST` 和相关测试的版本断言，并在 `verification.md` 记录实际运行结果。不支持的能力继续在诊断中明确标出。更新 `parity.md` 时只提升有证据的具体层级。

## 交付与真实桌面验收

先生成本地包、检查包内容和摘要，再通过官方插件管理器安装。真实 profile 的备份、安装及合成会话验收需明确授权；不自动重启用户正在工作的桌面。检查加载、打开工作台、应用与还原、技能发现和合成会话回退，再记录实际桌面结果。

公开提交不能携带安装程序、宿主源码、真实会话、数据库、密钥或原始诊断资料。新版本发布由维护者主动执行；本项目不在后台拉取代码或替换自身。
